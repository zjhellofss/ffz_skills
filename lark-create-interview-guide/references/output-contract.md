## 1. 内容保真规则

- 从目标章节提取问题；不要先凭常识列题，再回原文寻找佐证。
- 尽量沿用原文的核心句式、技术术语、变量名、公式顺序和示例。
- 删除重复解释、课堂口头语和与问题无关的铺垫。
- 把源章节里的绝对化表达改成与证据一致的限定表达，例如把“必然”“完全”“固定”为“一般”“在该实现中”“取决于配置”。
- 只纳入已验证的纠错；不要把未确认猜测写入面试答案。
- 技术实现发生版本变化时，以用户指定版本为准，并保留真实字段名、类名和路径。
- 面试答案直接陈述技术事实，不使用“源文档 + 中/把……”一类来源自指结构，也不使用“当前 + vLLM”一类无明确版本号的时态前缀；大小写和空格变化同样禁用。
- 需要说明实现差异时，写出具体版本、源码提交或 checkpoint/config 条件；没有具体版本依据时，删除时态前缀并使用准确的条件限定。

## 2. 选题门槛与题量

最终问题必须至少满足以下一项：

- **面试常考**：考察概念与原理、正确性、性能瓶颈、关键流程、方案对比、工程权衡、常用配置或典型排障，并且适合继续追问原因、实现和失效边界。
- **vLLM 核心**：涉及请求生命周期、调度与 batching、Model Runner、Attention/KV Cache、内存管理、并行通信、解码采样、模型加载、量化、性能优化、关键配置或可观测性，并会影响正确性、性能、兼容性、资源占用或排障。

只有 `interview_frequency=high` 或 `vllm_importance=high` 的候选才能独立成题。两个维度都为 `medium` / `low` 的内容只能并入高价值问题的答案，作为补充背景、实现细节或追问点。

不纳入只复述背景、无法独立成题、只考一次性辅助代码或冷门字段、只有短期版本记忆价值，或与其他题高度重复的候选。相邻候选考察同一能力时合并；一题包含多个可以独立追问的核心能力时拆分。

默认题量不设上限、下限或章节配额，所有通过门槛的题都应保留。不要为了凑整数、版面对称或模板配额增删问题。用户明确指定题数时，优先保留面试频率高或 vLLM 重要性高的题，再按知识前置关系和章节顺序取舍。

## 3. 候选题台账

写入前先在内部整理以下结构：

| 字段 | 含义 |
|---|---|
| question_no | 连续题号 |
| section | 面经中的知识层级 |
| question | 从原文陈述改写出的面试问题 |
| source_heading | 原文小节标题或具体内容名称 |
| source_block_id | 原文锚点 block ID |
| original_points | 必须保留的原文要点 |
| correction_evidence | 源码、论文或官方资料中的纠错依据 |
| answer | 适合 1～3 分钟口述的答案 |
| interview_frequency | `high` / `medium` / `low` |
| vllm_importance | `high` / `medium` / `low` / `not_applicable` |
| selection_reason | 入选或排除理由 |
| dedup_key | 用于合并近义候选的核心能力标识 |

先为全部候选填写台账，再应用选题门槛。最终入选题只设置一个主要来源锚点；确需综合多个小节时，在答案中综合，但主链接仍指向最能覆盖问题的小节。

## 4. 文档结构

推荐结构：

```text
标题
导读 callout
章节概览表
说明：问题来自原文，回答沿用原文并完成校错

一、基础原理
1. 问题
面试回答：先给结论……
解释机制、流程或关键细节……
补充边界、代价或工程权衡……
↗ 原文定位｜原文章节

二、典型算法
……

三、工程实现
……

四、面试回答策略（可选）
```

不要固定章节数；按原文内容自然分组。不要为每个小要点创建额外标题。

## 5. 回答分段规则

- 答案很短且只表达一个完整观点时，可以保留一个自然段。
- 一般答案使用 2～4 个自然段：首段给结论，中间段讲机制、流程或关键细节，末段按需补充边界、代价或工程权衡。
- 超过约 180 个非空白字符的答案必须拆成至少两个 `<p>`；不要用 `<br/>` 在同一个块里模拟分段。
- 只有首段带“面试回答：”标签，续写段直接承接正文，不重复标签。
- 分段依据是语义转折，不是固定字数切割；不要把连贯回答机械改成 bullet 列表。
- “原文定位”始终位于全部答案段落之后，不能插入答案中间。

## 6. XML 样式模板

顶层导读最多使用一个 callout：

```xml
<callout emoji="🎯" background-color="light-blue" border-color="blue">
  <p><b>N 道面试题 · M 个知识层级 · 每题附原文定位</b></p>
  <p>建议按“先给结论 → 再讲机制 → 最后补工程权衡”的顺序回答。</p>
</callout>
```

章节说明使用灰色普通段落：

```xml
<h2>一、基础原理与性能判断</h2>
<p><span text-color="gray">6 题 · 本章覆盖范围</span></p>
```

每题使用连续的一组块。下面展示三段式答案；短答案可以只保留首段，长答案通常保留 2～4 段：

```xml
<h3>1. 为什么……？</h3>
<p><b><span background-color="light-blue" text-color="blue">面试回答：</span></b>先直接给出结论……</p>
<p>接着解释机制、流程或关键细节……</p>
<p>最后按需补充边界、代价或工程权衡……</p>
<p><a href="https://tenant.feishu.cn/docx/DOC_TOKEN#SOURCE_BLOCK_ID">↗ 原文定位｜原文小节标题</a></p>
```

概览表只呈现真正的行列信息：

```xml
<table>
  <colgroup><col width="180"/><col width="100"/><col width="420"/></colgroup>
  <thead><tr><th background-color="light-gray">模块</th><th background-color="light-gray">题号</th><th background-color="light-gray">重点</th></tr></thead>
  <tbody><tr><td><b>基础原理</b></td><td>1～6</td><td>核心主题</td></tr></tbody>
</table>
```

保持颜色语义一致：蓝色表示信息或答案标签，绿色只表示推荐或成功，红色只表示错误或风险，灰色表示辅助说明。

## 7. 链接与校验

为源 URL 去掉已有 fragment，再拼接 `#source_block_id`。不要链接到搜索结果页、文档首页或不相关的大章节。

写入后检查：

- 每道题的台账中至少有一个高价值入选理由，且没有近义重复题或低价值填充题。
- 用户未指定题数时，题目数量等于通过选题门槛的候选数，不受固定模板约束。
- 每个 `<h3>` 后、下一个 `<h3>` 或 `<h2>` 前，恰好存在一个含“面试回答：”的段落。
- 超过约 180 个非空白字符的回答至少包含两个答案 `<p>`，只有第一个答案段落带“面试回答：”标签。
- 每题答案不含来源自指结构或无明确版本号的时态前缀。
- 同一区间内存在一个含“↗ 原文定位｜”的链接段落。
- 问题数、答案标签数、逐题来源链接数一致。
- 原文定位链接的 fragment 存在于源文档 block ID 集合。
- LaTeX 中的反斜线没有被 shell 或字符串转义吞掉；能用普通省略号表达时，不使用 `\ldots`。
- 代码比较符号已经 XML 转义，例如 `<` 写成 `&lt;`，`>` 写成 `&gt;`，`&` 写成 `&amp;`。
